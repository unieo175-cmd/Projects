## 一、系統概述

### 1.1 產品名稱
Payment 數據分析平台（Payment Analytics Dashboard）

### 1.2 產品定位
基於 Web 的支付數據分析與可視化平台，用於分析充值和提現交易數據，提供多維度的統計指標、時間分佈分析和報表導出功能。

### 1.3 目標用戶
- 支付運營團隊
- 財務分析人員
- 業務管理人員

### 1.4 系統架構

```
Payment 數據分析平台
├── 充值分析報表
│   ├── 總覽指標
│   ├── 極速（銀行卡）
│   ├── 極速（支付寶）
│   ├── 極速（微信）
│   └── 騙分沒到帳來找
├── 提現分析報表
├── 日/周報數據匯總
├── 騙分統計
├── 報表三方設定
└── PRD文件
```

### 1.5 技術棧

| 類別 | 技術 |
|------|------|
| 前端框架 | Vue.js 3 (Composition API) |
| 構建工具 | Vite 7 |
| 數據處理 | PapaParse, SheetJS (xlsx) |
| 部署 | GitHub Pages / Cloudflare Tunnel |

## 二、資料清洗規則

### 2.1 簡繁體字符處理

系統同時支援簡體與繁體中文資料，所有篩選條件皆包含兩種字符集：

| 簡體 | 繁體 | 用途 |
|------|------|------|
| `用户确认到帐` | `用戶確認到帳` | c2c 點確認判斷 |
| `商户确认到帐` | `商戶確認到帳` | 商戶確認判斷 |
| `银商确认到账` | `銀商確認到帳` | 銀商確認判斷 |
| `金额补单` | `金額補單` | 補單判斷 |
| `图文复核(已超时)` | `圖文複核(已超時)` | 超時判斷 |
| `审核中(已超时)` | `審核中(已超時)` | 超時判斷 |
| `明细补单` | `明細補單` | 明細補單判斷 |
| `补` | `補` | 掉單關鍵字 |

### 2.2 狀態正規化（normalizeStatus）

系統將原始狀態字符串正規化為統一格式，確保統計準確性：

| 原始狀態（含簡繁體） | 正規化後 |
|---------------------|----------|
| 金额补单 / 金額補單 | 金额补单 |
| 图文复核(已超时) / 圖文複核(已超時) | 图文复核(已超时) |
| 审核中(已超时) / 審核中(已超時) | 审核中(已超时) |
| 未充值 / 未充值 | 未充值 |

### 2.3 排除條件

以下記錄在計算時自動排除：

- 商戶包含 `test`（不區分大小寫）
- 商戶包含 `qa`（不區分大小寫）
- 商戶包含「線下」或「线下」（除非明確指定線下區塊）

### 2.4 欄位名稱對應

CSV/XLSX 欄位名稱同時支援簡繁體：

| 繁體欄位名 | 簡體欄位名 | 系統變數 |
|-----------|-----------|----------|
| 到帳金額 | 到账金额 | receivedAmount |
| 銀行卡編碼 | 银行卡编码 | bankCardCode |
| 銀行名稱 | 银行名称 | bankName |
| 收款商戶 | 收款商户 | merchant |
| 狀態 | 状态 | status |
| 充值金額 | 充值金额 | amount |
| 建立時間 | 建立时间 | createTime |
| 通知時間 | 通知时间 | notifyTime |
| 用戶等級 | 用户等级 | userLevel |

### 2.5 處理時間計算

```
處理時間（秒）= 通知時間 - 建立時間
平均處理時間 = Σ(處理時間) / 有效記錄數
```

### 2.6 商戶分類規則

| 分類 | 判斷條件 |
|------|----------|
| 銀行卡 | 商戶包含「极速充提3」且不含「支付寶/微信」 |
| 支付寶 | 商戶包含「支付寶」或「支付宝」 |
| 微信 | 商戶包含「微信」 |
| 線下 | 商戶包含「線下」或「线下」 |

### 2.7 術語定義

| 術語 | 說明 |
|------|------|
| **極速提** | 銀行卡編碼 = `AUCTION_PAYMENT_CARD` 的記錄，表示透過極速提系統配對的訂單 |
| **一般卡** | 銀行卡編碼有值且 ≠ `AUCTION_PAYMENT_CARD` 的記錄，表示透過一般銀行卡配對的訂單 |
| **c2c** | 極速提中用戶確認到帳的訂單，屬於 C2C（用戶對用戶）交易模式 |
| **信評上分** | 透過信用評分系統自動上分的訂單 |
| **掉單** | 到帳金額 > 0 但需要補單處理的訂單（狀態含「補」字） |

## 三、充值分析報表

### 3.1 功能概述

充值分析報表提供充值數據的總覽與各渠道分析，支援商戶篩選、日期範圍篩選、查詢與匯出 Excel 功能。

### 3.2 渠道切換

| 渠道 | 說明 |
|------|------|
| 全部 | 顯示所有渠道匯總數據（排除 test/qa） |
| 極速(銀行卡) | 銀行卡相關商戶（排除 test/qa/線下） |
| 極速(支付寶) | 商戶名稱包含「支付宝」或「支付寶」 |
| 極速(微信) | 商戶名稱包含「微信」 |

### 3.3 全部渠道 - 重要信息

| 指標 | 計算公式 |
|------|----------|
| **總申請筆數** | 商戶只排除 test/qa 的筆數加總 |
| **成功率** | 到帳金額 ≠ 0 的筆數 ÷ 總申請筆數 × 100% |
| **總充值成功（含掉單）** | 到帳金額 > 0 的筆數 |
| **總充值金額** | 到帳金額 > 0 的筆數的到帳金額加總 |
| **平均處理時間** | 到帳金額 > 0 的筆數，（通知時間 - 建立時間）的平均時間 |
| **無效申請** | 狀態含「取消」或 到帳金額 = 0 的筆數加總 |
| **掉單筆數** | 到帳金額 > 0 且狀態含「補」的筆數加總 |

### 3.4 圖表分析

#### 3.4.1 24小時交易分布

顯示每小時的充值交易分布圖表，包含：
- X 軸：時間（0-23 小時）
- 左 Y 軸：金額（柱狀 + 折線）
- 右 Y 軸：筆數（柱狀）

詳細樣式請參考第九章 UI/UX 設計規範。

#### 3.4.2 充值成功占比圓餅圖

顯示各渠道充值成功筆數的占比分布：

| 分類 | 說明 |
|------|------|
| **極速銀行卡** | 商戶含「极速充提3」且不含支付寶/微信，到帳金額 > 0 |
| **極速支付寶** | 商戶含「极速充提3」且含支付寶，到帳金額 > 0 |
| **極速微信** | 商戶含「极速充提3」且含微信，到帳金額 > 0 |
| **外部商戶** | 商戶以「外部商戶」開頭，到帳金額 > 0 |
| **線下** | 商戶含「線下」或「线下」，到帳金額 > 0 |

**數據範圍：** 所有商戶排除 test/qa，到帳金額 > 0

#### 3.4.3 銀行金額分佈條形圖

顯示充值金額前 10 名的銀行分佈：

|------|----------|

| **極速提** | 銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態 ≠「未充值」「審核中(已超時)」 |

|------|----------|

#### 3.6.6 c2c 區塊

| 項目 | 計算公式 |
|------|----------|
| **c2c** | 銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態包含「用戶確認到帳」或「用户确认到帐」 |
| **點確認（用戶確認到帳）** | 到帳金額 > 0，狀態包含「用戶確認到帳」或「用户确认到帐」 |
| **人工審核:通過** | 銀行卡代號包含 AUCTION，到帳金額 > 0，狀態包含「金額補單」或「金额补单」，處理時間 ≤ 11分鐘（660秒） |
| **超過11min補件後成功** | 條件一：銀行卡代號包含 AUCTION，到帳金額 > 0，狀態包含「金額補單」或「金额补单」，處理時間 > 11分鐘<br>**+**<br>條件二：銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態包含「商戶確認到帳」或「商户确认到帐」 |

#### 整體配對成功率
```
分子 = 銀行卡訂單成功極速提金額 + 支付寶訂單成功極速提(卡)金額 + 支付寶訂單成功極速提(寶)金額
分母 = 支付寶提現申請金額 + 銀行卡提現申請金額（來自提現分析）
配對成功率 = 分子 / 分母 * 100%
```

```

   - 排除不屬於任何分類的記錄

   - 同一訂單號保留最後一筆記錄
   - 確保統計不重複

3. 提現成功/失敗判斷
   - 成功：(說明=轉帳完成 OR 提現狀態含提現完成) 且 實際轉出金額≠0

4. 時間區段分類
   - 依處理時間（秒）分類到對應區段
   - 僅統計提現成功的記錄

5. 渠道統計
   - 依商戶名稱判斷渠道（銀行卡/支付寶/微信）
   - 各渠道獨立計算提現申請和平均時間

6. 從充值數據取得配對率相關數據
   - 充值申請、成功配對、訂單成功等來自 depositMetrics
```

### 5.3 週報重要指標

#### 5.3.1 充值申請

| 項目 | 計算公式 |
|------|----------|
| **充值申請筆數** | 銀行卡申請筆數 + 支付寶申請筆數 |
| **JS充值等待最終無配對** | 銀行卡小計 + 支付寶小計 |
| **無卡空單率** | JS充值等待最終無配對 / 充值申請筆數 × 100% |

#### 5.3.2 充值配對

| 項目 | 計算公式 |
|------|----------|
| **充值配對(配一般卡)** | 銀行卡一般卡 + 支付寶一般卡 + 一般寶 |
| **充值配對(配JS)** | 銀行卡極速提 + 支付寶極速提(卡) + 極速提(寶) |
| **充值配對(配一般提)** | 0（暫無數據） |
| **充值配對總數** | 配一般卡 + 配JS + 配一般提 |
| **充值配對率** | 充值配對總數 / 充值申請筆數 × 100% |

#### 5.3.3 訂單成功（筆數）

| 項目 | 計算公式 |
|------|----------|
| **訂單成功(一般卡)** | 銀行卡訂單成功一般卡 + 支付寶訂單成功一般卡 + 一般寶 |
| **訂單成功(Js+一般提)** | 銀行卡極速提 + 支付寶極速提(卡) + 極速提(寶) |
| **訂單成功(加總筆數)** | 一般卡 + Js+一般提 |
| **配對後成功率** | 訂單成功加總 / 充值配對總數 × 100% |

#### 5.3.4 訂單成功（金額）

| 項目 | 計算公式 |
|------|----------|
| **配一般卡充值訂單成功(金額)** | 銀行卡訂單成功一般卡金額 + 支付寶訂單成功一般卡金額 + 一般寶金額 |
| **配極速充值訂單成功(金額)** | 銀行卡訂單成功極速提金額 + 支付寶極速提(卡)金額 + 極速提(寶)金額 |
| **充值訂單成功(金額)總計** | 配一般卡金額 + 配極速金額 |

#### 5.3.5 騙分相關

| 項目 | 計算公式 |
|------|----------|
| **騙分金額** | 銀行卡人工金額 + 銀行卡信評金額 + 支付寶人工金額 + 支付寶信評金額 |
| **騙分成本占比** | 騙分金額 / 配極速充值訂單成功(金額) × 100% |
| **JS提現返利** | 提現記錄中的 merchantRebate（提現CSV第8欄H欄「商戶返利」）加總金額 |

#### 5.3.6 提現相關

| 項目 | 計算公式 |
|------|----------|
| **提現平均時間（卡）** | 銀行卡渠道平均處理時間 |
| **提現平均時間（寶）** | 支付寶渠道平均處理時間 |
| **提現失敗率** | 提現失敗筆數 / 總申請筆數 × 100% |

### 5.4 指標數據分析

#### 5.4.1 充值指標計算公式

| 指標 | 計算公式 |
|------|----------|
| **充值成功率** | 到帳金額 > 0 的筆數 / 總申請筆數 × 100% |
| **3分內占比** | 處理時間 ≤ 180秒的筆數 / 充值成功筆數 × 100% |
| **平均處理時間** | 到帳金額 > 0 的處理時間平均 |

#### 5.4.2 充值分類數據範圍

| 分類 | 數據範圍 |

| **整體** | 商戶只排除 test/qa |

| **微信** | 商戶含「微信」且不含 test/qa/線下 |
| **金寶** | 銀行卡代號 GB 開頭（排除 GB-Dahaomen），排除線下商戶 |
| **極速** | 銀行卡代號 AUCTION 開頭，排除線下商戶 |
| **第三方** | 銀行卡代號非 AUCTION/GB 開頭，或 GB-Dahaomen 開頭，排除線下商戶 |
| **非正向信評** | 狀態以「信用」或「信评」或「信評」開頭 |

#### 5.4.3 提現指標計算公式

| 指標 | 計算公式 |
|------|----------|
| **提現成功條件** | (說明=轉帳完成/转账完成/转帐完成 OR 提現狀態含提現完成/提现完成) 且 實際轉出金額≠0 |
| **提現成功率** | 提現成功筆數 / 總申請筆數 × 100% |
| **2分內占比** | 處理時間 < 120秒的筆數 / 提現成功筆數 × 100% |
| **平均處理時間** | 提現成功的處理時間平均 |
