## 一、系統概述

### 1.1 產品名稱
Payment 數據分析平台（Payment Analytics Dashboard）

### 1.2 產品定位
基於 Web 的支付數據分析與可視化平台，用於分析充值和提現交易數據，提供多維度的統計指標、時間分佈分析和報表導出功能。

### 1.3 目標用戶
- 支付運營團隊
- 財務分析人員
- 業務管理人員

### 1.4 系統架構

```
Payment 數據分析平台
├── 充值分析報表
│   ├── 總覽指標
│   ├── 極速（銀行卡）
│   ├── 極速（支付寶）
│   ├── 極速（微信）
│   └── 騙分沒到帳來找
├── 提現分析報表
├── 日/周報數據匯總
├── 騙分統計
├── 報表三方設定
└── PRD文件
```

### 1.5 技術棧

| 類別 | 技術 |
|------|------|
| 前端框架 | Vue.js 3 (Composition API) |
| 構建工具 | Vite 7 |
| 數據處理 | PapaParse, SheetJS (xlsx) |
| 部署 | GitHub Pages / Cloudflare Tunnel |

## 二、資料清洗規則

### 2.1 簡繁體字符處理

系統同時支援簡體與繁體中文資料，所有篩選條件皆包含兩種字符集：

| 簡體 | 繁體 | 用途 |
|------|------|------|
| `用户确认到帐` | `用戶確認到帳` | c2c 點確認判斷 |
| `商户确认到帐` | `商戶確認到帳` | 商戶確認判斷 |
| `银商确认到账` | `銀商確認到帳` | 銀商確認判斷 |
| `金额补单` | `金額補單` | 補單判斷 |
| `图文复核(已超时)` | `圖文複核(已超時)` | 超時判斷 |
| `审核中(已超时)` | `審核中(已超時)` | 超時判斷 |
| `明细补单` | `明細補單` | 明細補單判斷 |
| `补` | `補` | 掉單關鍵字 |

### 2.2 狀態正規化（normalizeStatus）

系統將原始狀態字符串正規化為統一格式，確保統計準確性：

| 原始狀態（含簡繁體） | 正規化後 |
|---------------------|----------|
| 金额补单 / 金額補單 | 金额补单 |
| 图文复核(已超时) / 圖文複核(已超時) | 图文复核(已超时) |
| 审核中(已超时) / 審核中(已超時) | 审核中(已超时) |
| 未充值 / 未充值 | 未充值 |

### 2.3 排除條件

以下記錄在計算時自動排除：

- 商戶包含 `test`（不區分大小寫）
- 商戶包含 `qa`（不區分大小寫）
- 商戶包含「線下」或「线下」（除非明確指定線下區塊）

### 2.4 欄位名稱對應

CSV/XLSX 欄位名稱同時支援簡繁體：

| 繁體欄位名 | 簡體欄位名 | 系統變數 |
|-----------|-----------|----------|
| 到帳金額 | 到账金额 | receivedAmount |
| 銀行卡編碼 | 银行卡编码 | bankCardCode |
| 銀行名稱 | 银行名称 | bankName |
| 收款商戶 | 收款商户 | merchant |
| 狀態 | 状态 | status |
| 充值金額 | 充值金额 | amount |
| 建立時間 | 建立时间 | createTime |
| 通知時間 | 通知时间 | notifyTime |
| 用戶等級 | 用户等级 | userLevel |

### 2.5 處理時間計算

```
處理時間（秒）= 通知時間 - 建立時間
平均處理時間 = Σ(處理時間) / 有效記錄數
```

### 2.6 商戶分類規則

| 分類 | 判斷條件 |
|------|----------|
| 銀行卡 | 商戶包含「极速充提3」且不含「支付寶/微信」 |
| 支付寶 | 商戶包含「支付寶」或「支付宝」 |
| 微信 | 商戶包含「微信」 |
| 線下 | 商戶包含「線下」或「线下」 |

## 三、銀行卡區塊計算準則

### 3.1 數據範圍

```
商戶包含「极速充提3」且不含支付寶/微信/test/qa/線下
```

### 3.2 充值申請筆數

| 項目 | 計算公式 |
|------|----------|
| **一般卡** | 銀行卡代號有值且 ≠ AUCTION_PAYMENT_CARD |
| **極速提** | 銀行卡代號 = AUCTION_PAYMENT_CARD |
| **建單成功等待無配對** | 銀行卡代號為空的筆數 |
| **取無卡06提示** | 數據來源：極速06統計表 |
| **充值申請筆數（總）** | 一般卡 + 極速提 + 建單成功等待無配對 + 取無卡06提示 |

### 3.3 成功配對

| 項目 | 計算公式 |
|------|----------|
| **一般卡** | 銀行卡代號有值且 ≠ AUCTION_PAYMENT_CARD |
| **極速提** | 銀行卡代號 = AUCTION_PAYMENT_CARD |
| **金額計算** | 使用充值金額（申請金額）計算 |

### 3.4 訂單成功

| 項目 | 計算公式 |
|------|----------|
| **一般卡** | 銀行卡代號有值且 ≠ AUCTION_PAYMENT_CARD，正規化狀態 ≠「未充值」「審核中(已超時)」 |
| **極速提** | 銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態 ≠「未充值」「審核中(已超時)」 |
| **信評上分** | 到帳金額 > 0 且狀態包含「信用」 |
| **平均處理時間** | 到帳金額 > 0 的平均處理時間 |

### 3.5 沒信評降等配卡

| 項目 | 計算公式 |
|------|----------|
| **條件** | 銀行卡代號 ≠ AUCTION_PAYMENT_CARD，到帳金額 ≠ 0，用戶等級 ≠ 0 且 ≠ -1 |
| **分組** | 按充值金額分組：100/200/300/500/1000/1500/2000/3000/5000/6000/7000/8000/9000/10000/15000/20000/30000/其他 |

### 3.6 c2c 區塊

| 項目 | 計算公式 |
|------|----------|
| **c2c** | 銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態包含「用戶確認到帳」或「用户确认到帐」 |
| **點確認（用戶確認到帳）** | 到帳金額 > 0，狀態包含「用戶確認到帳」或「用户确认到帐」 |
| **人工審核:通過** | 銀行卡代號包含 AUCTION，到帳金額 > 0，狀態包含「金額補單」或「金额补单」，處理時間 ≤ 11分鐘（660秒） |
| **超過11min補件後成功** | 條件一：銀行卡代號包含 AUCTION，到帳金額 > 0，狀態包含「金額補單」或「金额补单」，處理時間 > 11分鐘<br>**+**<br>條件二：銀行卡代號 = AUCTION_PAYMENT_CARD，到帳金額 > 0，狀態包含「商戶確認到帳」或「商户确认到帐」 |

### 3.7 三方代收區塊

#### 數據範圍
```
商戶不含「支付寶/微信/test/qa/線下」，到帳金額 > 0
```

#### 三方代收判斷
```
依據「報表三方設定」配置的卡代號動態識別，銀行卡代號以設定的卡代號開頭（不區分大小寫）
```

#### 動態配置說明

| 項目 | 說明 |
|------|------|
| **資料來源** | 報表三方設定（localStorage: `thirdPartyBankCards`） |
| **識別方式** | 銀行卡代號以設定的卡代號開頭（不區分大小寫） |
| **預設卡代號** | 大豪門(GB-Dahaomen)、匯通(HTc2c)、豆豆(DDF)、UC聚合(uc1020) |

#### 三方代收代碼識別函數

```javascript
// 動態讀取報表三方設定
const thirdPartyCards = JSON.parse(localStorage.getItem('thirdPartyBankCards') || '[]')

// 通用識別函數
isThirdPartyCard = (bankCardCode, cardCode) =>
  bankCardCode.toLowerCase().startsWith(cardCode.toLowerCase())
```

### 3.8 騙分沒到帳來找

| 項目 | 計算公式 |
|------|----------|
| **數據來源** | 騙分統計（依篩選日期範圍加總） |
| **人工** | 渠道 = 銀行卡，類型 = 人工 |
| **信評** | 渠道 = 銀行卡，類型 = 信評 |

### 3.9 商業平台

| 項目 | 計算公式 |
|------|----------|
| **數據範圍** | 商戶 = `极速充提3(银行卡)_CNX交易所` 或 `外部商户_500彩` |
| **充值申請** | 符合商戶的記錄筆數和充值金額 |
| **充值成功** | 狀態不含「未充值」且到帳金額 > 0 |

### 4.6 寶轉卡渠道及寶轉寶渠道

| 項目 | 計算公式 |
|------|----------|
| **寶轉卡渠道 申請** | 商戶包含「轉卡」且 銀行卡代號 = AUCTION_PAYMENT_CARD 且 銀行名稱 = 支付寶 |
| **寶轉卡渠道 成功** | 上述條件 + 到帳金額 ≠ 0 |
| **寶轉寶渠道 申請** | 商戶包含「宝)」且 銀行卡代號 = AUCTION_PAYMENT_CARD 且 銀行名稱 ≠ 支付寶 |
| **寶轉寶渠道 成功** | 上述條件 + 到帳金額 ≠ 0 |

#### 整體配對成功率
```
分子 = 銀行卡訂單成功極速提金額 + 支付寶訂單成功極速提(卡)金額 + 支付寶訂單成功極速提(寶)金額
分母 = 支付寶提現申請金額 + 銀行卡提現申請金額（來自提現分析）
配對成功率 = 分子 / 分母 * 100%
```

## 七、日/周報數據匯總

### 7.1 功能概述

日/周報數據匯總頁面整合充值和提現數據，提供關鍵業務指標的彙整報表，支援日期範圍篩選和 Excel 匯出功能。

### 7.2 頁面結構

```
日/周報數據匯總
├── 日期選擇器（起訖日期）
├── 週報重要指標
│   ├── 充值申請
│   ├── 充值配對
│   ├── 訂單成功（筆數）
│   ├── 訂單成功（金額）
│   ├── 騙分相關
│   └── 提現相關
├── 指標數據分析
│   ├── 充值數據（成功率/3分內占比/平均處理時間）
│   └── 提現數據（成功率/2分內占比/平均處理時間）
└── 匯出功能
```

### 7.3 週報重要指標

#### 7.3.1 充值申請

| 項目 | 計算公式 |
|------|----------|
| **充值申請筆數** | 銀行卡申請筆數 + 支付寶申請筆數 |
| **JS充值等待最終無配對** | 銀行卡小計 + 支付寶小計 |
| **無卡空單率** | JS充值等待最終無配對 / 充值申請筆數 × 100% |

#### 7.3.2 充值配對

| 項目 | 計算公式 |
|------|----------|
| **充值配對(配一般卡)** | 銀行卡一般卡 + 支付寶一般卡 + 一般寶 |
| **充值配對(配JS)** | 銀行卡極速提 + 支付寶極速提(卡) + 極速提(寶) |
| **充值配對(配一般提)** | 0（暫無數據） |
| **充值配對總數** | 配一般卡 + 配JS + 配一般提 |
| **充值配對率** | 充值配對總數 / 充值申請筆數 × 100% |

#### 7.3.3 訂單成功（筆數）

| 項目 | 計算公式 |
|------|----------|
| **訂單成功(一般卡)** | 銀行卡訂單成功一般卡 + 支付寶訂單成功一般卡 + 一般寶 |
| **訂單成功(Js+一般提)** | 銀行卡極速提 + 支付寶極速提(卡) + 極速提(寶) |
| **訂單成功(加總筆數)** | 一般卡 + Js+一般提 |
| **配對後成功率** | 訂單成功加總 / 充值配對總數 × 100% |

#### 7.3.4 訂單成功（金額）

| 項目 | 計算公式 |
|------|----------|
| **配一般卡充值訂單成功(金額)** | 銀行卡訂單成功一般卡金額 + 支付寶訂單成功一般卡金額 + 一般寶金額 |
| **配極速充值訂單成功(金額)** | 銀行卡訂單成功極速提金額 + 支付寶極速提(卡)金額 + 極速提(寶)金額 |
| **充值訂單成功(金額)總計** | 配一般卡金額 + 配極速金額 |

#### 7.3.5 騙分相關

| 項目 | 計算公式 |
|------|----------|
| **騙分金額** | 銀行卡人工金額 + 銀行卡信評金額 + 支付寶人工金額 + 支付寶信評金額 |
| **騙分成本占比** | 騙分金額 / 配極速充值訂單成功(金額) × 100% |
| **JS提現返利** | 提現記錄中的 merchantRebate 加總金額 |

#### 7.3.6 提現相關

| 項目 | 計算公式 |
|------|----------|
| **提現平均時間（卡）** | 銀行卡渠道平均處理時間 |
| **提現平均時間（寶）** | 支付寶渠道平均處理時間 |
| **提現失敗率** | 提現失敗筆數 / 總申請筆數 × 100% |

### 7.4 指標數據分析

#### 7.4.1 充值指標計算公式

| 指標 | 計算公式 |
|------|----------|
| **充值成功率** | 到帳金額 > 0 的筆數 / 總申請筆數 × 100% |
| **3分內占比** | 處理時間 ≤ 180秒的筆數 / 充值成功筆數 × 100% |
| **平均處理時間** | 到帳金額 > 0 的處理時間平均 |

#### 7.4.2 充值分類數據範圍

| 分類 | 數據範圍 |
|------|----------|
| **整體** | 商戶只排除 test/qa |
| **支付寶** | 商戶含「支付寶/支付宝」且不含 test/qa/線下 |
| **微信** | 商戶含「微信」且不含 test/qa/線下 |
| **金寶** | 銀行卡代號 GB 開頭（排除 GB-Dahaomen），排除線下商戶 |
| **極速** | 銀行卡代號 AUCTION 開頭，排除線下商戶 |
| **第三方** | 銀行卡代號非 AUCTION/GB 開頭，或 GB-Dahaomen 開頭，排除線下商戶 |
| **非正向信評** | 狀態以「信用」或「信评」或「信評」開頭 |

#### 7.4.3 提現指標計算公式

| 指標 | 計算公式 |
|------|----------|
| **提現成功條件** | (說明=轉帳完成/转账完成/转帐完成 OR 提現狀態含提現完成/提现完成) 且 實際轉出金額≠0 |
| **提現成功率** | 提現成功筆數 / 總申請筆數 × 100% |
| **2分內占比** | 處理時間 < 120秒的筆數 / 提現成功筆數 × 100% |
| **平均處理時間** | 提現成功的處理時間平均 |

#### 7.4.4 提現分類數據範圍

> **注意**：所有提現分類均按訂單號去重

| 分類 | 數據範圍 |
|------|----------|
| **整體** | (銀行卡 + 支付寶 + 微信) + 線下，按訂單號去重 |
| **支付寶** | merchant 含「支付寶/支付宝」，按訂單號去重 |
| **微信** | merchant 含「微信」，按訂單號去重 |

| **極速** | payoutCardCode 包含 AUCTION，按訂單號去重 |
| **第三方** | payoutCardCode 不為空且不包含 AUCTION，按訂單號去重 |
