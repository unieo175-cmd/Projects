## 一、系統概述

Payment 數據分析系統用於分析充值與提現數據，提供多維度的數據統計與報表功能。充值/提現報表支援 Excel 匯出，日/週報支援 TXT 匯出。

### 1.1 系統架構

Payment 數據分析
├── 充值分析報表
│   ├── 全部（總覽指標）
│   ├── 極速（銀行卡）
│   ├── 極速（支付寶）
│   └── 極速（微信）
├── 提現分析報表
│   ├── 全部（總覽指標）
│   ├── 極速（銀行卡）
│   ├── 極速（支付寶）
│   └── 極速（微信）
├── 日/週報數據匯總
├── 騙分統計
└── 報表三方設定

### 2.5 處理時間計算

處理時間（秒）= 通知時間 - 建立時間
平均處理時間 = Σ(處理時間) / 有效記錄數
顯示格式：HH:MM:SS（介面與匯出統一）

### 2.7 術語定義

| 術語 | 說明 |
|------|------|
| **極速提** | 銀行卡編碼 = `AUCTION_PAYMENT_CARD` 的記錄，表示透過極速提系統配對的訂單 |
| **一般卡** | 銀行卡編碼有值且 ≠ `AUCTION_PAYMENT_CARD`的記錄，表示透過一般銀行卡配對的訂單 |
| **一般寶** | 銀行卡代號有值且 ≠ `AUCTION_PAYMENT_CARD`，銀行名稱 = 支付寶／支付寶(企) 的記錄，表示透過支付寶配對的訂單 |
| **c2c** | 極速提中用戶確認到帳的訂單，屬於 C2C（用戶對用戶）交易模式 |
| **信評上分** | 透過信用評分系統自動上分的訂單 |
| **掉單** | 到帳金額 > 0 但需要補單處理的訂單（狀態含「補」字） |

## 三、充值分析報表

### 3.1 功能概述

充值分析報表提供充值數據的總覽與各渠道分析，支援商戶篩選、日期範圍篩選、查詢與匯出 Excel 功能。

### 3.1.1 篩選功能

| 功能 | 說明 |
|------|------|
| **商戶名稱** | 下拉選擇或搜索商戶 |
| **日期範圍** | （依**建立時間**篩選）起訖日期選擇，最大範圍一個月（數據可往回一個月） |
| **當日資料試算** | 每日 4am 計算前一天的數據。篩選日期為當日時，點選「當日資料試算」，資料範圍為當天 00:00:00 至查詢當下時間。 |
| **查詢** | 執行篩選條件 |
| **匯出 Excel** | 匯出當前篩選結果；Excel 排版與頁面不同，供運營貼上報告使用（格式詳見 Jira PAYM-721）。若有篩選特定商戶，檔案左上角顯示 `商戶名稱_JS數據_日期`（如：`极速充提3_杏耀_JS数据_20260513`） |

### 3.6 銀行卡區塊計算準則

> 📌 **數據範圍（適用本章節所有區塊）：** 充值紀錄，商戶包含「極速充提3」且不含支付寶/微信/線下/測試商戶。3.6.7 商業平台例外，詳見該節。

#### 3.6.1 充值申請筆數區塊

| 項目 | 計算公式 |
|------|----------|
| 標題 | 充值申請右側顯示總筆數和金額加總；計算公式：一般卡 + 極速提 + 建單成功等待無配對 + 取無卡06提示 + 無效申請 |
| **成功配對** | 顯示一般卡+極速提的筆數和充值金額加總 |
| **一般卡** | 充值紀錄中銀行卡代號有值且 ≠ AUCTION_PAYMENT_CARD的筆數和充值金額加總 |
| **極速提** | 充值紀錄中銀行卡代號 = AUCTION_PAYMENT_CARD的筆數和充值金額加總 |

### 4.5 提現失敗條件

> 📌 微信渠道騙分通常為 0，不另列出子項；騙分成本占比分母使用 5.4.3（銀行卡 + 支付寶極速提金額加總）。

| 項目 | 業務含義 | 計算方式 | 數據來源 |

### 5.7 週報重要指標-指標數據分析
> 📌 此區塊以單張對照表呈現「整體 / 支付寶 / 微信 / 金寶 / 極速 / 第三方 /非正向信評」7個分類的充值與提現關鍵指標。每列一個分類，左側充值欄位、右側提現欄位。

#### 5.7.1 充值指標計算公式
> 📌 對應指標數據分析表中「充值數據」三個欄位的計算公式。

**計算公式**
| 項目 | 業務含義 | 計算方式 | 數據來源 |
