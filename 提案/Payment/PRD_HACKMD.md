## 一、系統概述

Payment 正式版數據分析系統用於分析充值與提現數據，提供多維度的數據統計與報表功能。系統支援
CSV/XLSX 檔案導入，自動計算各項指標。

### 1.1 系統架構

Payment 正式版數據分析
├── 充值分析報表
│   ├── 總覽指標
│   ├── 極速（銀行卡）
│   ├── 極速（支付寶）
│   ├── 極速（微信）
│   └── 騙分沒到帳來找
├── 提現分析報表
├── 日/周報數據匯總
│   ├── 指標數據分析
│   └── 筆數計算
├── 騙分統計
├── 報表三方設定
└── PRD文件

## 二、資料清洗規則

### 2.1 簡繁體字符處理

系統同時支援簡體與繁體中文資料，所有篩選條件皆包含兩種字符集：

| 簡體 | 繁體 | 用途 |
|------|------|------|
| `用戶確認到帳` | `用戶確認到帳` | c2c 點確認判斷 |
| `商戶確認到帳` | `商戶確認到帳` | 商戶確認判斷 |
| `銀商確認到賬` | `銀商確認到帳` | 銀商確認判斷 |
| `金額補單` | `金額補單` | 補單判斷 |
| `圖文覆核(已超時)` | `圖文複核(已超時)` | 超時判斷 |
| `審核中(已超時)` | `審核中(已超時)` | 超時判斷 |
| `明細補單` | `明細補單` | 明細補單判斷 |
| `補` | `補` | 掉單關鍵字 |

### 2.2 狀態正規化（normalizeStatus）

系統將原始狀態字符串正規化為統一格式，確保統計準確性：

| 原始狀態（含簡繁體） | 正規化後 |
|----------------------|----------|
| 金額補單 / 金額補單 | 金額補單 |
| 圖文覆核(已超時) / 圖文複核(已超時) | 圖文覆核(已超時) |
| 審核中(已超時) / 審核中(已超時) | 審核中(已超時) |
| 未充值 / 未充值 | 未充值 |

### 2.3 排除條件

以下記錄在計算時自動排除：
**數據範圍：**
- 商戶勾選為測試商戶做判斷依據，勾選時，不計入該商戶
充值資訊設定>商戶列表>商戶資訊-類型
![image](https://hackmd.io/_uploads/H1MXegSc-x.png)

- 商戶包含「線下」或「線下」（除非明確指定線下區塊）

### 2.4 欄位名稱對應

CSV/XLSX 欄位名稱同時支援簡繁體：

| 繁體欄位名 | 簡體欄位名 | 系統變數 |
|------------|------------|----------|
| 到帳金額 | 到賬金額 | receivedAmount |
| 銀行卡編碼 | 銀行卡編碼 | bankCardCode |
| 銀行名稱 | 銀行名稱 | bankName |
| 收款商戶 | 收款商戶 | merchant |
| 狀態 | 狀態 | status |
| 充值金額 | 充值金額 | amount |
| 建立時間 | 建立時間 | createTime |
| 通知時間 | 通知時間 | notifyTime |
| 用戶等級 | 用戶等級 | userLevel |

### 2.5 處理時間計算

處理時間（秒）= 通知時間 - 建立時間
平均處理時間 = Σ(處理時間) / 有效記錄數

### 2.6 商戶分類規則

| 分類 | 判斷條件 |
|------|----------|
| **銀行卡** | 商戶包含「極速充提3」且不含「支付寶/微信」 |
| **支付寶** | 商戶包含「支付寶」或「支付寶」 |
| **微信** | 商戶包含「微信」 |
| **線下** | 商戶包含「線下」或「線下」 |
| **外部商戶** | 商戶包含「外部」 |

### 2.7 術語定義

| 術語 | 說明 |
|------|------|
| **極速提** | 銀行卡編碼 = `AUCTION_PAYMENT_CARD` 的記錄，表示透過極速提系統配對的訂單 |
| **一般卡** | 銀行卡編碼有值且 ≠ `AUCTION_PAYMENT_CARD`的記錄，表示透過一般銀行卡配對的訂單 |
| **c2c** | 極速提中用戶確認到帳的訂單，屬於 C2C（用戶對用戶）交易模式 |
| **信評上分** | 透過信用評分系統自動上分的訂單 |
| **掉單** | 到帳金額 > 0 但需要補單處理的訂單（狀態含「補」字） |

## 三、充值分析報表

### 3.1 功能概述

充值分析報表提供充值數據的總覽與各渠道分析，支援商戶篩選、日期範圍篩選、查詢與匯出 Excel功能。

**數據來源**：充值紀錄

### 3.1.1 篩選功能

| 功能 | 說明 |
|------|------|
| **商戶名稱** | 下拉選擇或搜索商戶 |
| **日期範圍** | 起訖日期選擇，最大範圍一個月（數據可往回一個月） |
| **當日資料試算** |  點擊後解鎖當日日期選擇，並以當日資料重新計算指標   |
| **查詢** | 執行篩選條件 |
| **匯出 Excel** | 匯出當前篩選結果 ，運營有指定格式請看 jira單 PAYM-721/ excel排版與頁面不一樣,excel 排版用來讓運營貼上報告所以與頁面不一樣|

### 3.2 渠道切換

|------|------|
| 全部 | 顯示所有渠道匯總數據（排除 test/qa） |

### 4.5 提現失敗條件

說明 ≠ "轉帳完成/转账完成/转帐完成" AND 實際轉出金額 = 空白或0（按訂單號去重）

> 📌 此條件與「成功」不互補。若訂單同時不滿足成功也不滿足失敗（例如金額=0但說明=轉帳完成），會被視為**處理中**狀態，不計入總申請數（4.6「總申請=成功+失敗」）。實務上這類中間態極少。

**整體配對成功金額對提現申請比公式**（純文本支付寶區塊最後一行）
- 分子 = 銀行卡極速提 + 支付寶極速提(卡) + 支付寶極速提(寶) 三項訂單成功金額之和。

- 比值 = 分子 / 分母 × 100%（分母為 0 時顯示 0%）。
